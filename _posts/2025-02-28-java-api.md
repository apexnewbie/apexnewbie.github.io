## Sorting

### 1. Arrays.sort()

- **用途：** 对数组进行排序。  
- **特点：**  
  - 支持对基本数据类型和对象数组排序。  
- **示例：**

  ```java
  int[] arr = {3, 1, 2};
  Arrays.sort(arr);  // 对基本类型数组进行排序
  
  ```


---

### 2. Collections.sort()

- **用途：** 对 `List` 集合进行排序。  
- **特点：**  
  - 适用于对象集合。  
- **示例：**

  ```java
  List<Integer> list = new ArrayList<>(Arrays.asList(3, 1, 2));
  Collections.sort(list);  // 使用自然顺序排序
  
  ```

---

### 3. List.sort() 方法

- **用途：** 从 Java 8 开始，`List` 接口新增了 `sort` 默认方法，可以直接对 `List` 排序。  
- **特点：**  
  - 功能与 `Collections.sort()` 类似，但更加简洁。  
- **示例：**

  ```java
  List<Integer> list = new ArrayList<>(Arrays.asList(3, 1, 2));
  list.sort(null);  // 使用自然顺序排序
  
  // 使用自定义排序规则
  list.sort((a, b) -> a - b);
  ```

## ThreadLocal

**ThreadLocal 的作用：**

- **线程局部存储**：  
  为每个线程提供独立的变量副本，不同线程间互不干扰。

- **数据隔离**：  
  避免多线程共享变量时的同步问题，每个线程读写自己专属的数据，适用于存储用户上下文、事务信息等。

- **简化编程**：  
  通过 ThreadLocal，可以在不使用同步机制的前提下实现线程安全的数据访问。

---

**示例代码：**

```java
public class ThreadLocalDemo {
    // 定义一个 ThreadLocal 变量，存储每个线程的独立数据
    private static ThreadLocal<Integer> threadLocal = new ThreadLocal<>();

    public static void main(String[] args) {
        Thread threadA = new Thread(() -> {
            threadLocal.set(100);  // 为当前线程设置值
            System.out.println("Thread A value: " + threadLocal.get());
        });

        Thread threadB = new Thread(() -> {
            threadLocal.set(200);  // 为当前线程设置不同的值
            System.out.println("Thread B value: " + threadLocal.get());
        });

        threadA.start();
        threadB.start();
    }
}
```

**讲解要点：**

- 每个线程通过 `threadLocal.set()` 设置自己的值，互不干扰。  
- 调用 `threadLocal.get()` 时，每个线程获得的是自己设置的值，而不会受到其他线程影响。  
- 这种机制非常适合用于需要线程隔离数据的场景，简化了并发编程的复杂性。

## `StringBuffer` & `StringBuilder`

`StringBuffer` 和 `StringBuilder` 是 Java 中用于高效操作字符串的两个类，它们的功能非常相似，但在线程安全性和性能上有显著区别。以下是它们的详细对比：

---

### 一、核心区别

| 特性              | `StringBuilder`          | `StringBuffer`           |
|-------------------|-------------------------|--------------------------|
| **线程安全**      | 非线程安全              | 线程安全                 |
| **性能**          | 更高（无同步开销）      | 较低（同步开销）         |
| **适用场景**      | 单线程环境              | 多线程环境               |
| **方法同步**      | 未使用 `synchronized`   | 使用 `synchronized`      |
| **引入版本**      | Java 5 (JDK 1.5)        | Java 1.0                 |

---

### 二、详细解释

#### 1. **线程安全性**
- **`StringBuffer`**：
  所有方法都使用 `synchronized` 关键字修饰，确保在多线程环境下是线程安全的。
  适合在多个线程同时操作同一个字符串的场景。

- **`StringBuilder`**：
  方法没有使用 `synchronized`，因此是非线程安全的。
  适合在单线程环境下使用，性能更高。

#### 2. **性能**
- **`StringBuilder`**：
  由于没有同步开销，性能优于 `StringBuffer`。
  在单线程环境下，推荐使用 `StringBuilder`。

- **`StringBuffer`**：
  由于方法使用了 `synchronized`，在多线程环境下会带来额外的性能开销。
  只有在需要线程安全时，才使用 `StringBuffer`。

#### 3. **适用场景**
- **`StringBuilder`**：
  单线程环境，如局部变量、方法内部的字符串操作。

- **`StringBuffer`**：
  多线程环境，如多个线程共享同一个字符串缓冲区。

---

### 三、代码示例

#### 1. **StringBuilder 示例**
```java
StringBuilder sb = new StringBuilder("Hello");
sb.append(" World"); // 追加字符串
sb.insert(5, " Java"); // 插入字符串
sb.delete(0, 6); // 删除字符
sb.replace(0, 5, "Hi"); // 替换字符
sb.reverse(); // 反转字符串
System.out.println(sb.toString()); // 输出结果

```

#### 2. **StringBuffer 示例**
```java
StringBuffer sb = new StringBuffer();
sb.append("Hello").append(" World");
System.out.println(sb.toString()); // 输出 "Hello World"
```

---

### 四、最佳实践

1. **单线程环境**
   优先使用 `StringBuilder`，性能更高。

2. **多线程环境**
   如果需要线程安全，使用 `StringBuffer`。

3. **避免滥用 `StringBuffer`**
   在单线程环境下，使用 `StringBuffer` 会带来不必要的性能开销。

4. **预分配容量**
   如果知道最终字符串的大致长度，可以在创建 `StringBuilder` 或 `StringBuffer` 时指定初始容量，避免频繁扩容。

## 三者对比总结：

|               | final                  | finally                  | finalize()                 |
|---------------|------------------------|--------------------------|----------------------------|
| 类型          | 关键字                 | 异常处理语句块           | Object类方法               |
| 用途          | 修饰类、方法、变量     | 异常处理中的资源清理     | 对象回收前资源清理         |
| 调用时机      | 编译期                 | 运行时异常处理后一定执行 | JVM垃圾回收对象前（不确定）|
| 是否推荐使用  | 推荐                   | 推荐                     | 不推荐，已废弃 (Java 9+)   |

---

## ⚠️ 注意：

- 自Java 9起，`finalize()`方法被标记为**废弃（Deprecated）**，原因是JVM不能保证`finalize()`方法一定会被执行，更无法保证执行的时机。
- 推荐使用`try-with-resources`结构或显式调用资源的关闭方法（如`.close()`）替代`finalize()`来确保资源的释放。

比如：
```java
// 推荐做法
try (BufferedReader br = new BufferedReader(new FileReader("file.txt"))) {
    // 使用br
} // 自动调用close()
```

---

## 总结：

- **final：** 限制、修饰类、方法、变量。
- **finally：** 异常处理中的强制执行代码块。
- **finalize()：** JVM调用对象回收前的方法（**已废弃，不建议使用**）。
