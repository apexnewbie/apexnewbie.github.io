## Hash Map

**1. 开放寻址法：**  
- **原理**：  
  - 所有数据都存储在哈希表的数组中。  
  - 当发生冲突时，通过探测算法（如线性探测、二次探测、双重散列）寻找下一个空槽位存储元素。  

- **优点**：  
  - 数据连续存储，利用缓存优势，提高查找速度。  
  - 不需要额外的数据结构来存储冲突数据。  

- **缺点**：  
  - 当负载因子较高时，探测效率降低，查找和插入的性能可能急剧下降。  
  - 删除操作较为复杂，为避免破坏探测链，常需使用“懒删除”策略。

---

**2. 封闭寻址法（链地址法）：**  
- **原理**：  
  - 哈希表的每个槽位保存一个链表（或其他结构，如红黑树）。  
  - 所有映射到同一槽位的元素都存储在对应的链表中。  

- **优点**：  
  - 能有效处理高负载因子，冲突多时依然能保持较好的查找效率。  
  - 插入和删除操作较为简单，只需对链表进行操作。  

- **缺点**：  
  - 需要额外内存存储链表节点。  
  - 在极端情况下（所有元素都哈希到同一槽位），链表可能退化为线性查找，影响性能。

---

**3. 哈希扩容（扩容和再散列）：**  
- **触发条件**：  
  - 负载因子 = 当前元素数量 / 桶总数
  - 当哈希表的负载因子达到预设阈值（如 Java HashMap 默认 0.75）时触发扩容，以保持较低冲突率和较高效率。

- **扩容过程**：  
  - 创建一个更大容量的新数组（通常为原容量的2倍）。  
  - 对现有元素重新计算哈希值，将其重新映射到新数组中，这个过程称为“再散列”。

- **注意事项**：  
  - 扩容和再散列操作开销较大，可能会导致短暂的性能下降。  
  - 合理设置初始容量和负载因子，可以有效减少扩容次数，平衡空间和时间效率。

---

### HashTable 和 HashMap的区别

**相同之处：**  
- 都是基于哈希表实现的 Map 数据结构，存储键值对。  
- 都实现了 Map 接口，提供基本的 put、get、remove 等操作。  

**不同之处：**  
- **线程安全性：**  
  - *Hashtable*：所有方法均经过同步处理，天然线程安全。  
  - *HashMap*：默认不支持线程安全，多线程环境下需自行同步。  

- **性能表现：**  
  - *Hashtable*：由于同步机制，在单线程环境下性能稍逊。  
  - *HashMap*：在单线程环境下性能更好，且更常用于非并发场景。
